# Existing WriteFlex operations

These names were verified in the app's capability source. Availability and parameter schemas come from the connected app, not this list. They are not CLI commands; do not invent a `writeflex` executable or import application internals to bypass policy.

| Capability | Use and result |
| --- | --- |
| `files.list`, `files.read` | Read supported workspace content. |
| `prose.edit` | Propose an exact, unique `oldText` replacement. Keep each edit to one sentence or short phrase; include `category` and a short `summary` per the current schema. |
| `prose.insert`, `prose.move` | Propose content insertion or movement using the exposed schema. |
| `objects.insert` | Propose a validated object from inner markup. |
| `frontmatter.set` | Propose metadata additions/changes; lists are arrays. |
| `frontmatter.normalise` | Normalise an existing block; it does not add or set metadata. |
| `housekeeping.create_file`, `housekeeping.rename_file` | Perform requested housekeeping through the app's write path. |
| `plan.read` | Read a Folio's running order with each part's title, gloss, role, file (null when unwritten), word count, synopsis, label, priority, status and open flags, plus strays and whether an Index Note exists. Start Folio work here. Direct. |
| `plan.propose` | Propose running-order changes (insert, move, remove, adopt, materialise, setRole) as ONE proposal the writer accepts, edits or discards. Remove takes a part out of the order and keeps its file; nothing is deleted. The only way to change a running order through the app. Proposal. |
| `folio.create_manifest` | Declare a Folio only when no manifest exists. |
| `scraps.list`, `scraps.add` | Use only if the current app binds its shared scrap store. |
| `widgets.list` | Read a document's widgets: each with its ordinal (1-based, document order), source line, path as typed, and whether it resolves inside the Workspace or why not. No line numbers; refer to a widget by ordinal or source line. Direct, nothing is written. (WriteFlex 0.22.) |
| `widgets.insert` | Propose embedding an HTML file that already exists in the Workspace. Arguments: `path` (the document), `file` (workspace-relative path of the HTML file; web addresses, files outside the Workspace and non-HTML files are refused), `position` (`"start"` after any frontmatter, `"end"` the default, or the ordinal of a widget to follow). Writes one line, `[Simulation: <path from the document's folder>]`, with blank lines around it; never creates or changes the HTML file. Proposal: the writer accepts or discards it. (WriteFlex 0.22.) |
| `widgets.create` | Propose a NEW widget. Arguments: `path` (the document), `fileName` (a name ending `.html`; cleaned to lower-case letters, digits and hyphens), `html` (the complete self-contained page), `title` (the caption; added as `<title>` if the page has none), `position` (as widgets.insert). `path` must be a Markdown document in a visible folder, and neither it, its folders nor `assets/` may be a link. The writer is shown the new file's path and full source in the proposal. On accept WriteFlex saves exactly that page in `assets/` beside the document (created if missing; an existing name gets `-2`, `-3`..., never overwritten) and writes the embed line `[Simulation: assets/<file>]`; on discard nothing is written. A page over 1 MiB, or one that obviously needs the network or another file, is refused with the reason; that check is an early warning, not what keeps the widget offline (the sealed frame does). Proposal; gated by the Agent Permissions "create files" and "prose edits" switches, both of which must be on. (WriteFlex 0.22.) |
| `widgets.remove` | Propose removing one embed line by its ordinal from `widgets.list`. Arguments: `path`, `ordinal`. The HTML file stays on disk. Proposal. (WriteFlex 0.22.) |
| `research.capture` | File ONE reusable unit (a table, a visualisation, a piece of evidence, a snippet, a search result or a widget description) as its own Markdown file in the `research/` folder beside the document, or in its Folio's `research/` folder, and index it for search. Arguments: `project` (workspace-relative path of the document being worked on, or a folder), `title`, `kind` (`evidence`, `table`, `visualisation`, `snippet`, `search`, `widget`), `body` (the unit itself, Markdown), and optionally `prompt` (the question that produced it), `sources` (a list: `scout:<passage id>`, a URL or `file:<path>`; never retype a search hit without its passage id) and `artefact` (workspace-relative path of a non-Markdown file to copy in beside the description). WriteFlex runs the `scout capture` command for you and reports the new file and whether it was indexed; it only ever makes a new file, so it applies directly and deleting the file undoes it. Refused with a plain reason when scout is not installed or the folder is not in the Workspace. (WriteFlex knowledge step two.) |

`research.capture` is the same action as the palette command "Capture to research…" and the `writeflex capture` command line (added in WriteFlex 0.26.0-alpha.9). Outside the app, use `scout capture` directly (see the skill). The planned Research panel adds no verb you can call yet.

In the Folio workspace the writer's Delete on a part moves its file to the Folio bin with Undo; no operation here deletes a Folio file or writes to `.folio-bin/`. Assistant turns on a Folio also receive its notes, evidence and source availability, the map's proposed path and its `AGENTS.md`; treat missing or changed sources as unresolved.

The application may stage a call instead of applying it. Report the returned state accurately. A refused/staged operation is not permission to reproduce it with a filesystem write. There is no external content CLI established by this skill.

Moves of Folio files made outside WriteFlex (shell, `git mv`) are not an app operation: WriteFlex version history, keyed by path, does not follow them. Write the move map described in content formats (Moving files in a Folio) so the writer can reattach history. The `AGENTS.md` block is written by WriteFlex on Make Folio or Restore only; an agent never writes it.
