# Durable Record Patterns

Use plain language with users. Internal terms such as control plane, backlog, side quest, context window, and progressive disclosure should not be prerequisites.

## Core Principle

Chat is useful for exploration and feedback. Information that must survive the conversation—decisions, plans, instructions, lessons, and things to return to—needs a durable home.

Explain the principle and trade-off in the user's context. Do not prescribe a slogan or imply that every message needs archiving.

## Smallest Useful Pattern

Use one chronological journal containing:

- concise confirmed summary;
- what happened and what was decided;
- notes and ideas;
- plans and things to return to;
- working-style experiments;
- original dictation or source material underneath the summary.

Do not echo a long dictation into the live conversation. Preserve it in the source chat and include it in the durable entry when one is created.

At the next session, read the current summary and only the relevant journal entries. Do not reload the entire history indiscriminately.

## File-Based Pattern

When the environment supports durable files, recommend:

1. **Current instructions:** short, human-readable approved guidance.
2. **Journal:** chronological decisions, experiments, notes, plans, and raw accounts.
3. **References:** supporting instructions loaded only when relevant.
4. **Lessons:** reusable findings promoted from repeated experience, with provenance.

Keep the central instructions short and link to relevant supporting detail instead of copying it. Treat the journal as authoritative history and current instructions as the maintained view of what is presently in force.

## Worked Example: A Linked File-Based Setup

A user who does repeated work with a file-capable agent might keep:

- one chronological journal for decisions, plans, observations, and source notes;
- a short file containing the working instructions currently in force;
- supporting reference files that the agent opens only when relevant;
- a brief resumption note naming the current focus and next action;
- selected lessons promoted from patterns that have survived repeated use.

Advantages:

- stronger retrieval and a visible history of changes;
- reliable resumption across sessions;
- separation between current guidance and historical evidence;
- less dependence on the user's memory for every open thread.

Costs:

- setup and maintenance;
- conventions and folders to learn;
- storage, backup, and synchronisation decisions;
- best results require a desktop agent with file access.

This is a synthetic example of the pattern, not a template every user must reproduce. A simpler journal may be enough.

## Chatbot Fallbacks

When files are unavailable:

- produce editable custom instructions;
- propose a compact memory entry and obtain approval before saving it;
- create a dated resumable Markdown or document summary for later upload;
- encourage periodic export of important work rather than reliance on chat navigation alone;
- verify or qualify claims about what a particular product retains.

Preserve at least the current goal, decisions, useful context, things to return to, and next action.

## Change Model

- **Trying:** proposed and under test.
- **Working well:** supported by experience.
- **Standing instruction:** approved for continued use.

Allow routine observations to enter the journal automatically only in a user-approved disk-based setup. Require review before changing standing instructions, custom instructions, or persistent chatbot memory.

Never erase an earlier preference merely because it changed. Record the replacement, date, reason, and any context where the older guidance still applies.

## Resume Pattern

End substantive work with:

- current focus;
- what changed;
- decisions and reasons;
- things to return to;
- next action;
- source locations when available.

On resumption, present the current focus and next action first. Offer deeper history only when needed.
