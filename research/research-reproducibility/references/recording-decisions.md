# Recording decisions

## Proportion and existing tools

Start from the question the next researcher must be able to answer. Reuse automatic receipts; add the missing human decision and evidence links. Do not duplicate raw logs in prose. A notebook may be sufficient for exploration; a run manifest is useful when connecting fixed inputs to execution and outputs. Do not require a database, service or new schema merely to use this skill.

Before a run, prefer a small source snapshot plus a manifest over a retrospective account. Record the actual exposed model identifier and settings; do not invent a pinned snapshot. Record command/code revision and dependencies needed for the reconstruction target. An unchanged model prompt across two arms does not imply identical harness, tools, history or context.

If context is not exposed, record the available request, known harness/application version, tools or attachments and the coverage limit. Do not block all useful work on impossible full-context capture. A visible transcript is evidence of visible messages, not proof of the complete inference input. Exact saved request text, a reconstructed request and a reusable template must be labelled separately.

## Decisions and amendments

A material entry answers: what changed, who authorised it, why, what evidence supports it, which results are affected, and what happens next. Use the actual decision date when known; keep the record's creation date distinct when reconstructing history. Do not backdate new knowledge.

Freeze selection criteria before inspecting outcome scores where the research design requires it. Retain first valid outputs when that is the agreed rule. Technical retries and discretionary revisions are different. A failed provider/model target does not authorise silent substitution. Record an authorised substitution and its effect on the comparison.

## Usage and resource claims

Keep raw usage and derived totals separate. Identify independent requests across stages and exports; the same response reused for reconciliation is not a second request. Conversely, identical text from separate real requests does not make those requests duplicates. Repeated cumulative counters and inherited fork histories require explicit reconciliation, not summation. If request identity is unavailable, state the resulting uncertainty instead of choosing a convenient total.

Preserve attempts with missing usage as unknown. Capture rates, currency and retrieval date when producing a price estimate; use verified applicable rates. Do not add cached tokens to a total that already includes them, or reasoning tokens to output when they are already included. Do not combine a subscription's hypothetical API equivalent with actual external API expenditure as a bill. Separate research setup effort from the marginal work of repeating an established procedure.

## Reconstruction and checking

State the test performed: inspect a manifest, compare bytes, rebuild a view from saved data, rerun deterministic analysis, call a model again, or assess meaning with people. Each supports a different claim. Visual similarity does not establish byte identity. A byte-identical HTML rebuild does not validate a translation or prove comprehension.

Compare rendered or packaged content with the preserved source/output. A successful-stage label alongside an empty field is a packaging discrepancy until the original record is checked; do not infer a failed call or fabricate missing text. Preserve actual exported/downloaded bytes when delivery identity matters. No new sharing is authorised by this skill.

## Worked continuation

The author changes a questionnaire from “any visit” to “last visit” after the first analysis. The old notebook calls the analysis current; a replacement is only planned.

Append a dated correction to the existing notebook with the author's approval and both source versions. Mark the old run as completed for its original source, not current for the approved revision. Keep the replacement planned. Before rerunning, snapshot the approved source and available instructions/request; record inaccessible context as a limit. After execution, link actual outputs and checks.

If a successful response appears twice under the same request ID, count that request once while preserving both files. A failed first attempt with no usage stays unknown. If the response reports 1,000 input tokens including 800 cached and 120 output including 50 reasoning, known total usage is 1,120. A reported USD 0.03 estimate is not a verified charge. Record those distinctions without making a separate entry for every inspection.
