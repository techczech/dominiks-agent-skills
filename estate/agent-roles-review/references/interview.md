# Interview: how the operator works

Ask at most four questions at a time. Start from what the operator has already said; skip anything you can see in their files or tools. Plain questions, no jargon from this skill.

## Work

- What do you mostly have agents do: code, apps, documents, research, data, something else? Roughly what share?
- How big is a typical piece of work: minutes, an afternoon, several days?
- Which work do you check by using it, and which can you not see (data handling, security, background jobs)?
- What has gone wrong that cost you most: lost data, wasted hours, something wrong sent or published, bills?

## Tools and money

- Which agent tools and subscriptions do you have, and which do you actually use?
- Which limit do you hit first, and how do you know when you are close?
- Are there models you want used only when you ask?
- How much do you want to spend per month, and on what should it go first?

## Checking

- How do you want to be asked to check something: in chat, a list, a review page, an issue?
- How much of your time per day can go to checking?
- When should an agent stop and ask rather than carry on?
- Do you want a working version early, or a finished one later?

## Rhythm

- Do you run several sessions at once? Do you want to watch them?
- Do you work on several machines? Does anything run overnight or unattended?
- When should the roles be reviewed: on a date, when a new model ships, after an incident?

## After the interview

Restate the answers as constraints in one short list and confirm it before drafting. Each constraint should point at the principle it selects or rules out.
